# Phase 11 — Interview Mastery & Architect Conversations

From the README §4 phase table, extended with ★ architect-conversation practice (the learner's goal:
hold their own with any senior architect). Cycle 11.1 **runs in parallel from Phase 5 onward**
(human mocks, format practice) and becomes the focus after Phase 10.

## Cycle 11.1 — Formats, humans, pressure

| ID | Type | Session |
|---|---|---|
| 11.1.1 | L | ★ **Company formats**: Google (estimation + deep dive), Meta *System Design* vs *Product Architecture* (API/data/client contract), Amazon (operations, ownership, cost), fintech (correctness), startups (pragmatism) |
| 11.1.2 | M | ★ **Product Architecture drill** (Meta-style): design the API + data model + pagination + real-time updates for a product feature |
| 11.1.3 | M | ★ **"Tell me about a system you built"**: prepare 2 stories of your own systems: architecture, scale, trade-offs, what failed, what you'd change |
| 11.1.4 | M | ★ **Curveball drills**: mid-interview requirement changes, hostile "why not X?", "you have 5 min left" |
| 11.1.5 | 👥 | **Human mock series**: ≥ 6 across Phases 5–11 (peers, ex-colleagues, or mock platforms). Feedback goes into `/wrap` |
| 11.1.6 | R | Review |

## Cycle 11.2 — ★ Architect conversations

| ID | Type | Session |
|---|---|---|
| 11.2.1 | AR | ★ **Joining an unfamiliar system**: the mentor, as the system's principal architect, walks through a complex existing architecture; the learner builds a mental model fast by asking the right questions (README objective: "understand an unfamiliar system quickly") |
| 11.2.2 | AR | ★ **Decision meeting**: two senior architects (both played by the mentor) disagree, e.g. Kafka vs managed queue, Postgres vs DynamoDB. The learner facilitates, extracts the constraints, and drives to a recommendation |
| 11.2.3 | AR | ★ **Incident post-mortem review**: a real-style outage write-up; the learner finds root causes, contributing factors and the architectural fixes |
| 11.2.4 | AR | ★ **Vendor/technology evaluation**: build vs buy for a search or observability stack, with a cost/risk memo |
| 11.2.5 | R | Review |
